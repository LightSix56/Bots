# Bots

Три Telegram-бота на Python, запускаемые по расписанию GitHub Actions. Внешних платных API нет: RSS, Open-Meteo и IMAP Mail.ru используются бесплатно.

| Скрипт | Что делает | Расписание |
|---|---|---|
| `bot.py` | Пересылает письма от `@mirea.ru` из ящика Mail.ru | каждый час (`7 * * * *`) |
| `news.py` | Дайджест из RSS: РБК, Хабр, Коммерсантъ, 3DNews | 12:00 МСК (`0 9 * * *`) |
| `weather_bot.py` | Погода на сегодня и сводка на завтра по Подольску и Москве | 03:53 МСК (`53 0 * * *`) |

## Модули

| Файл | Назначение |
|---|---|
| `tg.py` | Отправка в Telegram: нарезка по 4096 символов без разрыва HTML, повтор при 429/5xx, откат на отправку без разметки при 400 |
| `config.py` | Чтение токенов и `TG_CHAT_ID` из окружения |
| `storage.py` | Файл состояния: атомарная запись, TTL записей, кулдаун уведомлений об ошибках |
| `console.py` | UTF-8 вывод в консоль (на Windows по умолчанию cp1251, печать эмодзи падает) |

## Настройка секретов

Скопируйте `.env.example` и заполните. В GitHub это Settings → Secrets and variables → Actions.

| Секрет | Обязателен | Назначение |
|---|---|---|
| `MAIL_USER`, `MAIL_PASS` | для `bot.py` | Ящик Mail.ru. Пароль — пароль приложения, не основной |
| `MAIL_TG_BOT_TOKEN` | для `bot.py` | Токен бота, который шлёт письма |
| `NEWS_TG_BOT_TOKEN` | для `news.py` | Токен бота новостей |
| `WEATHER_TG_BOT_TOKEN` | для `weather_bot.py` | Токен погодного бота |
| `TG_CHAT_ID` | везде | Получатель. Запасного значения в коде нет: без него бот завершится с ошибкой, а не отправит сообщение в чужой чат |

## Использование

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -t .   # 269 тестов
python news.py --check                       # вывод в консоль вместо Telegram
python weather_bot.py --check
```

Флаг `--check` (или `CHECK_MODE=1`) печатает результат в консоль и не обращается к Telegram. Состояние при этом не изменяется.

## Состояние

История отправленного лежит в `data/<bot>_state.json` и сохраняется между запусками через `actions/cache`. В git она не коммитится: раньше `news.yml` коммитил `seen.json` после каждого запуска, из-за чего 246 из 306 коммитов репозитория были служебными.

`seen.json` в корне оставлен как источник разовой миграции: при первом запуске `news.py` переносит из него 500 хэшей, чтобы уже отправленные новости не ушли повторно. После того как кэш состояния наполнится, файл можно удалить.

Запись в состояние происходит только при подтверждённой доставке. Если Telegram не принял сообщение, письмо не помечается прочитанным, а хэш новости не сохраняется — и то и другое вернётся в следующий запуск.

## Тесты

```bash
python -m unittest discover -s tests -t .
```

Покрыты: нарезка сообщений и повторы Telegram, чтение конфигурации, атомарность и TTL состояния, единицы ветра и агрегация прогноза, разбор RSS и дедупликация, разбор писем и дедупликация по `Message-ID`, соответствие workflow и кода по именам переменных.

Сквозная проверка на живых RSS и Open-Meteo (Telegram не вызывается):

```bash
python tools/verify_live.py
```

Проверка неиспользуемых импортов:

```bash
python tools/check_imports.py
```

## Замечания по эксплуатации

* `bot.py` ищет письма по `SINCE` без флага `UNSEEN`: письмо, прочитанное на телефоне или в веб-интерфейсе, тоже будет переслано. Повторная отправка исключается историей по `Message-ID`.
* Тело письма читается через `BODY.PEEK[]`, иначе сам факт чтения снимает флаг «прочитано» на сервере.
* IMAP-соединение открывается с таймаутом 30 с, у jobs стоит `timeout-minutes`. Сокет без таймаута на зависшем сервере держал job до 6 часов.
* Скорость ветра запрашивается с `wind_speed_unit=ms`. Без этого параметра Open-Meteo отдаёт км/ч, и порог «10 м/с» срабатывал почти ежедневно.
* Советы по одежде считаются скриптом, без обращения к LLM: результат детерминирован.
